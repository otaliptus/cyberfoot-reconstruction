The archived original executable remains unchanged. By default, package-loader.js applies an in-memory compatibility modification at launch: Randomize returns immediately and RandSeed is initialized from browser cryptographic randomness. This avoids repeated coarse-clock reseeding; the Borland random-number generator and registration checks are unchanged. Add rng=original to the emulator URL to run the byte-identical original executable. Original copyrights and registration restrictions remain applicable.

The default isolated runtime is a modified MultiThreaded build from Boxedwine 26R1.0 commit d7d5a1421bd781a81cbdf8f222cced11a7ebd76e, built with Emscripten 4.0.23 and a 12-worker pool. It adds optional UI callback wakeups, deferred XFlush presentation, atomic dirty-state handling and diagnostic counters. Both improvements are enabled by default; forkmode=0 disables them for comparison. runtime-loader.js selects this runtime when SharedArrayBuffer and cross-origin isolation are available, with engine=single as an explicit fallback. boxedwine-shell.js is modified to concatenate seventeen same-origin Wine filesystem parts and three original-game parts, report progress and report fetch errors. Optimized packaging: duplicate immutable Wine .nls locale tables are downloaded once and restored as ordinary files in the in-memory ZIP before Wine starts. The build verifies the resolved bytes of every retained file against the source archive. Download parts are content-addressed and integrity checked. The browser downloads up to four parts concurrently. scripts/pack-emulator.py in the project repository reproduces the packages.

Startup optimization: runtime-loader.js prefetches the configured root and game packages while WebAssembly initializes. All optimized packages share a four-download limit; the normal loader consumes each prefetched package once. Locale aliases reuse the integrity-checked compressed streams, avoiding redundant decompression and reducing temporary archive memory. No additional game-code changes are made by these startup optimizations.

English/Turkish package profile: omit unrelated Windows code-page tables and game translations from the downloadable packages. Keep Windows ANSI1252/1254, OEM437/850/857, ASCII20127, Latin-1/Latin-5 28591/28599, all shared Unicode/case/normalization/sorting tables, English language97/971/default and Turkish192. Original source archives remain intact. packages.json lists every omitted path, and pack-emulator.py reproduces this profile. Game rules, graphics, teams, players, executable registration checks and retained translations are unchanged.

Runtime-only delivery (15 September 2026): opt/wine/include/ development header and IDL entries are omitted from the Wine package. This directory is used to build Windows programs, not to run the bundled game. All retained archive contents remain byte-identical; the original archives are retained as build inputs.

Threaded UI scheduling (15 September 2026): event-pump.js uses Emscripten's existing timer scheduler in visible tabs to service native UI requests between display frames. Hidden tabs and the single-thread fallback retain the original animation-frame behavior. Add pump=original to retain the original event scheduler. Guest time sources, match timers, game assets, executable and RNG configuration are not changed by this scheduling adjustment.

Corresponding source for the modified threaded runtime (15 September 2026): source/boxedwine-cyberfoot-source.tar.gz contains the patched source, headers, bundled libraries, platform code and web build files. source/README.md gives build instructions; source/runtime.patch, source/build-manifest.json, source/archive.json and source/LICENSE.txt provide the exact changes, tested binary identities, source archive identity and GPL-2.0 license. Source files are downloads only and are not fetched when playing. The fork preserves the game logic, game clocks, registration behavior and graphics. fork-runtime.js configures runtime switches, while runtime-loader.js versions JS/WASM URLs together.

Whole-program compiler optimization (15 September 2026): the threaded fork compiles all translation units with -flto and links with -O3 -flto using Emscripten 4.0.23. This reduces compiled runtime size and permits cross-file optimization of existing emulator routines. It adds no tail-call requirement and does not change the game executable, assets, rules, clocks or RNG configuration. The build uses Build/LTO to avoid stale objects from earlier compiler flags. Exact flags and binary identities are in source/build-manifest.json.

Memory-access optimization (15 September 2026): the threaded web build inlines the existing permitted, single-page RAM branches of byte/word/dword reads and writes. The complete original implementations remain out-of-line fallbacks for page boundaries, permissions, special pages and code invalidation. Address checks, translation, guest clocks, game executable and rules are unchanged. Source and reproducible Build/MemoryFast instructions are in the corresponding-source download.
